# Signed issue intake for Leo

Implementation specification for the first GitHub event delivered to the local coordinator. The operator selects one repository, installation and owning machine. The service accepts an intake report and obtains a short local acknowledgment from the repository's Claude Code coordinator. Development, work-card approval, GitHub comments and labels are outside this slice.

## Runtime contract

Run `node dist/src/webhook-service.js` in the service container. Bind port 19739 and publish to host loopback. `JAM_REPOSITORY`, `JAM_REPOSITORY_ID` and `JAM_INSTALLATION_ID` identify the topic. Read the webhook signing secret from `JAM_WEBHOOK_SECRET_FILE` and place the SQLite journal in `JAM_STATE_DIR` on durable writable storage. The container uses Node 22 with the built-in SQLite module. GET /health reports HTTP listener and database readiness. The processing state is visible in the journal.

## Delivery and acceptance

1. POST /github accepts at most 2 MiB of raw body, checks the HMAC-SHA256 signature in constant time, then parses the payload. A signed ping receives success. Only GitHub issues/opened for the configured installation and repository qualify. Validate the delivery UUID, numeric issue number and text types. A payload over the wire limit receives HTTP 413 and requires delivery inspection in GitHub. An event from another repository or installation cannot launch Claude.
2. Commit the normalized intake and GitHub delivery ID before returning HTTP 202. SQLite uniqueness covers redelivery of the same ID and a second ID for the same opened issue in this installation/repository. Reopening is a different event and falls outside this slice. Failure to persist returns a retryable server error.
3. One consumer services this repository serially. It claims queued rows transactionally, creates or resumes the repository's saved Claude Code session and submits only the configured repository name, numeric issue number and delivery UUID. Keep issue text in the journal and out of the persistent model session. Disable tools, skills, plugins/hooks from user/project configuration, external MCP and permission prompts. Keep Claude's working directory dedicated to this service. Request an acknowledgment bound to the issue and delivery. Validate the structured result before committing it. No dispatch path to a developer or external write exists in this service.
4. On restart, dispatch queued rows. A row marked as running at interruption moves to needs-review; inspect the existing session before any manual replay. A timeout, unexpected CLI output or ambiguous exit also requires review. An absent or unconfirmed repository session cannot silently switch to a new identity. Stop the consumer from processing later deliveries while session state requires review. The GitHub acknowledgment means the event reached the journal, independently of model availability.

## Verification

Exercise invalid and missing signatures, malformed and oversize input, wrong topic, unapproved issue text, exact redelivery and duplicate opened notifications. Verify intake text, including claims of approval, never enters Leo’s prompt or grants permission. Simulate restart before dispatch and during dispatch. Verify tools are disabled, the coordinator's session persists for subsequent events and a failed invocation leaves an actionable state without retrying the event blindly. Then open a real issue in the private test repository and match GitHub's delivery, issue number, Claude session and accepted acknowledgment in the durable journal. This experiment exercises notification delivery; future task analysis must retrieve the current work card, comments and their attachments as defined in PRD JB-35. Receipt does not demonstrate attachment retrieval or human approval.

## Runtime safeguards and operator recovery

The service starts under Linux `flock -n -F` holding `JAM_STATE_DIR/owner.lock` through the process lifetime. Use a Docker named volume; Node 22.13 or later is required. Run SQLite quick_check on startup. The service writes the topic, installation and a newly allocated session UUID to the journal on the first start, before accepting deliveries. Keep `JAM_STATE_DIR/leo` as the fixed Claude working directory. A change to the recorded topic or working directory fails startup. The initial call uses the recorded UUID, later calls resume that UUID. Do not run another CLI session against that identity. Container authentication and its single writer are specified in SERVICE.md.

Store at most 512 title characters and 8,192 body characters locally. The stdin envelope contains only validated identifiers. Claude runs with `--safe-mode --tools "" --strict-mcp-config --disable-slash-commands --permission-mode dontAsk --permission-prompts none`. Its fixed system prompt and tool-free environment contain no external effect path. The invocation timeout is two minutes and stdout is limited to one MiB. The public health check reports readiness without event contents; local review shows intake status, including a blocked dispatch queue.

Use `node dist/src/webhook-service.js review list` to inspect recorded events from the service container. After inspecting an ambiguous result, resolve with `review resolve DELIVERY acked|abandon|requeue OPERATOR resume|unused`. Supply an attributable operator identity and the observed session condition. Only use unused if the recorded session has never processed an event and has no harness history. Resolution updates the event and session marker and appends an audit entry in one transaction. The service resumes polling local queued rows after resolution.
